GPU 参考实现 vs NPU 迁移实现：逐模块 / 逐张量对照

项目：/root/bytedance-onetrans/　版本：v1　日期：2026-11-14 参考侧：GPU_Reference（commit 8febd7e，零改动），在 CPU 上执行（本机无 GPU） 迁移侧：OneTrans_NPU，npu:0（Ascend950DT_9582，CANN 9.1.0，torch_npu 2.7.1.post4） 复现：python3 tests/compare_ref_vs_npu.py --all、python3 tests/compare_mask_semantics.py 原始日志：results/compare_gpu_vs_npu_950_20261114.txt

参数规模说明：本对照用配置（d_model=64 / ns_len=8 / seq_len=32 / pyramid=3）为 2,227,970 个参数、747 个梯度张量；冒烟/精度脚本的默认配置约 6.0M，两者不是同一配置，数字不可互引。

对照口径：同一 seed=1234 构造权重（两侧同一份 models/taac_onetrans.py）→ 同一份落盘输入（B=8）→ 前向 logits → cross-entropy loss → 反向全参数梯度。不换数据、不换超参、不换模型代码，只换设备。

这两个参数在该配置下被 mask 乘穿（贡献恒 0），参考侧留下 2.8e-10 的浮点残渣，NPU 侧精确为 0。如果直接用 rel = max|Δ| / max|g_ref| 计算，会得到 rel=1.0、cos=0.0，看上去像"梯度完全不一致"——这是分母陷阱，不是实现差异。

正确口径（本次采用）：两侧量级都低于 max(1e-8, 全局|g|max×1e-10) 时判为「数值零梯度」，单独计数、不参与 rel_max。本例 2 个，占 747 的 0.27%。

paper_causal 允许位抽查（前 3 行 × 前 6 列，1=True=允许）：

ref  float  [1, 0, 0, 0, 0, 0]

结论：bool 的 True 与 float 的「未填 -inf」是同一集合，语义等价（注意方向：float 用 -inf 表示禁止，bool 用 True 表示参与；写反会静默改训练结果）。

loss 0.809698 0.809698 Δ=5.96e-08

口径提醒：kernel 段 3.66× ≠ 模型 3.66×。该实现成本主要在「每个 token 组一套独立 KQV/FFN 参数」，attention 只占小头；端到端 4 次里有 1 次是负值，说明 +1~4% 的收益处在噪声边缘，只能按"小幅、不稳定"记账。此前记录过的 46.3 µs → 12.3 µs 是单次 attention op 探针口径，与本次「模型内 3 个 block 的 attention 段总和」不可混比。

7. 结论与边界

成立的部分：单卡 fp32 下，NPU 实现与 GPU 参考实现在 logits / loss / 全部 747 个梯度上分别做到 1e-7 / 1e-8 / 1e-6 级一致；bf16 下为 1e-3 / 1e-4 / 1e-2 级；4 种 mask 语义完全等价。

边界： 1. 参考侧在 CPU 上执行（本机无 GPU）。CPU fp32 与 GPU fp32 之间的差异未测——若 GPU 上用了 TF32/cuDNN 非确定性算法，差值可能大于 1e-6。 2. 只对照了 paper_causal 端的 forward/backward；origin / bimask_soft / bimask_hard 只对照了 mask 张量，未做端到端 loss/梯度对照。 3. 对照是单 die；多卡数值一致性由 tests/ddp_equiv_npu.py 单独验证（W=2 fp32 worst rel|Δg|=1.2e-6）。 4. 未做长训收敛对照（同数据同 seed 跑 N 步比 loss 曲线）。
