0 结论：推荐顺序

排序数据集用途理由
1TAAC2026 官方 sample（HF TAAC2026/data_sample_1000，1,000 行 / 120 列）打通数据链路、对齐上游唯一与上游 utils/taac_data.py 的 schema 完全一致，代码零改动；但只有 1,000 行，只能跑通不能收敛
2Ali-CCP（阿里点击-转化预测，约 42 M 训练 + 42 M 评估）真实训练首选唯一同时具备 CTR + CVR 双标签、用户行为序列、数值+类别特征的工业级公开集；与论文「双任务 + 多行为序列」形态最接近
3Taobao Ad Display/Click（约 2,656 万条曝光，114 万用户，8 天）次选真实训练特征齐全（用户画像 / 广告 / 100 M+ 行为日志），社区预处理脚本多；规模比 Ali-CCP 小
4TAAC2025 TencentGR-10M / 1M（HF，CC-BY-4.0）公开可直取的规模数据合法性/许可最干净、HF 直下；但它是生成式召回的候选集格式（item_id + retrieval_id + 15 列特征 dict），没有多行为长序列、没有 CTR/CVR 标签
5Tenrec / KuaiRand / MicroLens序列建模能力对比多行为长序列齐全（MicroLens ~10 亿交互、KuaiRand 3.2 亿、Tenrec 4 场景），但无工业 CTR 标签，需自造标签与负采样
6Amazon Reviews 2023（约 5.71 亿条评论）超长用户序列序列最丰富、可截断到 1190；无曝光/点击标签，只能做「下一物品」或自造 CTR
7Criteo 1TB（约 40 亿行）压 NS 侧与表容量极限无序列，纯数值+类别特征；适合单独压 HKV/NS 输入侧，不适合 OneTrans 整体

3 落地步骤（接入真实数据要做的事）

  1. 数据获取：Ali-CCP / Taobao 走天池申请（需实名），TAAC2026 sample / TencentGR / Amazon 走 HF 直下。
  2. schema 对齐：本仓 OneTrans_NPU 只有合成数据路径；上游 GPU_Reference/utils/taac_data.py 是 TAAC2026 专用加载器 —— 接 Ali-CCP 需新写字段映射（用户/物品/上下文 → user_int_feats_* 等价物）。
  3. 序列对齐：论文 seq 1190（多层行为融合 + [SEP]）→ Ali-CCP/Taobao 原始序列远短于此，需 pad + mask 或改用「短序列 + 金字塔 schedule 自适应」。
  4. NS 特征对齐：数值特征走 Bucketizer（已实现），类别特征直接给 id（已实现），F=12 域需按数据集实际域数改。
  5. 先 1 die 跑通再 16 die：1 die 用 1,024 桶级小表验证 loss 能降（本仓已验证：0.7446 → 0.0000），再放 16 die。
