# Round 1 实验结果（16 卡 OneTrans-S）

方案见 `docs/PLAN_OPT_ROUND1.md`；profile 依据见 `docs/PROFILE_16DIE_BOTTLENECK.md`。
基线口径：16 die（122+111）· 每卡 2048 · 全局 32,768 · bf16 + bool mask(FAv4) + 激活重算 + `ONETRANS_NS_BMM=1`。

## 0 一句话结论

**E1b（融合 rms_norm）有效：16 die 步时 1443.9 → 1228.6 ms（−14.90%），吞吐 22,694.9 → 26,671.4 sps（+17.52%），
MFU 10.35% → 12.17%，HBM 52.27 → 47.57 GB，且精度比手写链更接近 fp64。**
E1a / E4 判无效（0.03% / 0.0%），E5 在每卡 2048 上 OOM。

## 1 结果总表

| 编号 | 改动 | 开关 | 16 die 步时 | Δ | 判定 |
|---|---|---|---:|---:|---|
| 基线 | ns_bmm | — | 1443.9 ms | — | — |
| **E1b** | **融合 `npu_rms_norm`** | `ONETRANS_FUSED_NORM=1` | **1228.6 ms** | **−14.90%** | ✅ **有效（进主表）** |
| E1b + E4 | 再加 `--ddp-strict` | — | 1228.7 ms | +0.01% | ❌ 无效（保留开关，不计收益） |

| E5 | 只重算 FFN（保留 attention 激活） | `ONETRANS_CKPT_SCOPE=ffn` | — | OOM | ⛔ 每卡 2048 不可行（82.48/91.75 GiB） |

E1b 附带：kernel 数 3,083 → **2,762 个/步**（−321）；HBM 峰值 −4.70 GB；MFU +1.82 pp。

## 2 E1b 为什么有效（逐算子证据）

同一份 kernel_details 对比（臂 A = 仅 ns_bmm，臂 C = +fused_norm，均 3 个稳态步）：

| 算子 | 臂 A（手写链） | 臂 C（融合） | Δ |
|---|---:|---:|---:|
| `aclnnMul_MulAiCore` | 151.6 ms / 140 次 | **0** | **−151.6** |
| `aclnnPowTensorScalar_Square` | 27.9 ms / 28 次 | **0** | −27.9 |
| `aclnnDivs_RealDivAiCore` | 22.2 ms / 17 次 | 0 | −22.2 |
| `aclnnPowTensorScalar_Pow` | 14.4 ms / 28 次 | 0 | −14.4 |
| `aclnnMean_ReduceMeanAiCore` | 13.1 ms / 29 次 | 0 | −13.1 |
| `aclnnMuls_MulAiCore` | 14.3 ms / 109 次 | 0.3 ms | −14.0 |
| `aclnnReduceSum` | 32.2 ms / 107 次 | 19.1 ms / 79 次 | −13.0 |
| `aclnnAdd_AddAiCore` | 130.8 ms / 251 次 | 109.0 ms / 237 次 | −21.8 |
| `RmsNorm`（融合前向） | 0 | 29.7 ms / 28 次 | +29.7 |
| `RmsNormGrad`（融合反向） | 0 | 35.1 ms / 14 次 | +35.1 |
| **净变化** | | | **≈ −213 ms**（实测 −227.8 ms，余为小算子） |

判读：手写链的真实成本是 **一整套向量算子**（Mul 占最大头 151.6 ms，因为 `bf16×fp32 weight` 还会把张量提成 fp32 再走一遍
`Mul`/`Add`），不只是 `Square + Pow`。换成 `npu_rms_norm` 后，前向 28 次调用只对应 29.7 ms、反向 14 次 35.1 ms。

**自纠（推翻本会话先前结论）**：我在 `docs/PROFILE_16DIE_BOTTLENECK.md` §3-B3 里写「手写 RMSNorm 链 = Square 27.9 + Pow 14.4
≈ 42.6 ms/步，可省 60~80 ms」——**低估约 6 倍**。实际整条链 ≈ 280 ms/步（19%），实测省下 215 ms。原因是我只看了 Square/Pow
两个名字，漏了同属该链的 `Mul`/`Divs`/`Mean`/`Add`（Mul 单项就是 Square 的 5 倍）。该文档已同步更正。

## 3 E1a / E4 / E5 为什么不行

- **E1a（dtype 归位）**：UT 证实输出确实从 fp32 变 bf16、且精度不降（max_rel 3.888e-03 → 3.891e-03），但 16 die 实测 +0.03%。
  原因是手写链的成本主体（`Mul` 151.6 ms 等）不在「多一次 cast」上，而在「fp32 域内多做一遍向量运算」——只改输出 dtype 不改这条链，时间不会动。
- **E4（`find_unused_parameters=False`）**：0.01%，说明 autograd 图遍历在这套步时里可忽略（host 侧与 1228 ms 的 device 时间不同量级）。
- **E5（只重算 FFN）**：OOM。保留 attention 激活需多留 ~30 GB，实测 82.48 GiB 已分配、差 1.43 GiB 就撞 91.75 GiB 上限。
  `attn` 作用域（保留 FFN 中间态）按内存账更不可能（FFN 中间态 ≈ 7.6 GB × 7 block），未再试。

## 6 下一轮候选（按证据排）

1. **backward 专项**：bwd 占 75.7%，其中重算 ≈24%；先做 `attn`/`ffn` 之外的分块重算实验（如按 block 交替）或
   「重算 + 更小 per-card batch」的组合，属**改主对比轴，需拍板**。
2. **Cast 仍未动**（726 次/步、185.3 ms，fused_norm 前后完全不变）：它来自 autograd 内部（无用户栈），
   要动就得改权重 dtype 策略（原 E2），zeus 侧历史为负收益，需单独立项试。
3. **Cat 95 ms / 步**：其中 `_project_one`（ns_bmm 的 seq/ns 合并）是主源，可改为预分配 + 原地写入，逐位等价类。
4. **Transpose 82 ms / 步**：多来自进 FA 前的布局与反向转置，与 attention 分块方案绑定。


## 7 追加（第二轮）：步时被计了 4 遍，不是 kernel 效率问题

用 `--no-backward` 只跑前向做对照（8 die · 每卡 2048 · fused_norm）：

| 段 | 耗时/步 | kernel/步 | 单遍 MFU |
|---|---:|---:|---:|
| 仅前向 | 309.2 ms | 643 | **48.24%** |
| 完整步 | 1,235.1 ms | 2,762 | 12.17% |
| ⇒ backward(+opt) | 925.9 ms | 2,119 | — |

分解：`925.9 − 309.2 = 616.7 ms` 的真反向 ≈ 2 × 309.2（反向 FLOPs 是前向的 2 倍），
即 **前向 1 遍 + 重算 1 遍 + 真反向 2 遍 = 4 遍算力**，两遍各自效率都在 48% 左右（fwd 48.24% / 真反向 48.5%）。
整体 MFU 12.17% ≈ 48.4% ÷ 4 —— **瓶颈是「遍数」，不是单遍效率**。

Cast 归属也随之澄清：完整步 185.3 ms/726 次，仅前向 62.1 ms/236 次 ⇒ backward 侧 123.3 ms/490 次（autograd 内部，
与优化器无关：opt.step 只有 3.4 ms）。

## 8 追加（第二轮）：去掉重算的可行档

| 档（16 die · 全局 32,768 · n=8） | 步时 | 全局 sps | 每卡 sps | MFU | HBM |
|---|---:|---:|---:|---:|---:|
| 每卡 2048 + 重算（对齐论文 per-GPU） | 1,228.6 ms | 26,671.4 | 1,667.0 | 12.17% | 47.57 GB |
| **每卡 1024×累加2，无重算** | **959.2 ms** | **34,161.9** | **2,135.1** | **15.58%** | 70.66 GB |

- 全局 batch / 卡数不变；变化只有 per-GPU micro-batch 与是否重算。
- 数学目标一致（micro-batch 均值 ÷ 累加数 = 整批均值），但 bf16 重排 + AdamW 非线性使 loss 轨迹分叉
  （step4：0.93893 vs 0.92159）⇒ 不可逐值比对，也不能拿来做精度回归。
- 累计（起点 1,942.1 ms / 16,872.3 sps / MFU 7.70%）→ 959.2 ms / 34,161.9 sps / MFU 15.58%：
  **步时 −50.61%、吞吐 +102.47%**；与论文 407 ms 并列 **2.36×**。

## 9 DDP 开销隔离（1 die vs 16 die 同档）

| 配置 | 步时 | 每卡 sps | MFU | HBM |
|---|---:|---:|---:|---:|
| 1 die（world_size=1，无 DDP） | 1,227.5 ms | 1,668.4 | 12.18% | 47.23 GB |
| 16 die（122+111，DDP + 跨机 UB allreduce） | 1,228.6 ms | 1,667.0 | 12.17% | 47.57 GB |
| Δ | **+0.09%** | −0.08% | — | — |

⇒ 分布式侧（梯度桶 + 16 卡跨机 allreduce）净开销 **≈0.09%**，与 profile 中「通信净暴露 0.33%」互证。
⇒ 反向里那 490 次 Cast（123.3 ms/步）**不是 DDP 造成的**（也不是优化器：opt.step 只有 3.4 ms），
   只能来自 autograd 内部——按每个 matmul/每个权重在 autocast 边界的 dtype 往返。

### 9.1 若要吃掉这 123 ms，需要什么样的改动（待拍板）

- 方案：给每个权重维护 bf16 shadow（前向用它 ⇒ 不再每算子 cast），反向梯度直接落在 shadow 上，
  每步把 shadow 的 bf16 梯度**一次性**转回 fp32 累进 master；优化器仍只更新 fp32 master。
- 代价：要自己写 param 的影子机制 + 与 DDP 的 grads 视图配合，属**结构性改动**，不是开关能解决的；
  上限收益 ≈ 123 ms / 1,228.6 ms ≈ **10%**（若全部 cast 都来自权重）；若只来自部分算子，收益按比例缩水。
- 风险：梯度精度语义改变（bf16 梯度累加），需按 tol 门禁（2 步 loss rel + 梯度 relative diff）单独立项验证。

## 10 追加：`_project_one` 去 cat（E7，有效）

`torch.cat([seq, ns])` → 预分配 + 两段原地写。8 die 同档 profile 逐算子（前 → 后）：
`Cat_ConcatD 51.4→7.8`、`Cat_CastAiCore 42.2→6.4`、`InplaceCopy_Cast 143.1→78.5`、`InplaceCopy_Transpose 76.6→26.6`；
新增 `FA 附属转置 0→27.9`、`ViewCopy 32.1→54.7`、`TensorMove 2.1→24.0`；整步 **1,235.1 → 1,121.7 ms（−113.4 ms）**。

| 档（16 die · 全局 32,768 · n=8） | 前 | 后 | Δ | 吞吐 Δ | MFU |
|---|---:|---:|---:|---:|---|
| A 每卡 2048+重算 | 1,228.6 ms | **1,112.1 ms** | **−9.48%** | +10.48% | 12.17→13.44% |
| B 每卡 1024×2 无重算 | 959.2 ms | **892.5 ms** | **−6.95%** | +7.48% | 15.58→16.75% |

精度：非逐位。写入值相同，但新缓冲地址/对齐变化会改变下游 kernel 分块与 fp32 累加顺序 ⇒ loss 相对差 ≤2e-4
（step0 一致 0.69804；step1 1.26852 vs 1.26844；step3 1.06913 vs 1.06892）。属 bf16 噪声级等价。

**累计（起点 1,942.1 ms / 16,872.3 sps / MFU 7.70% / HBM 52.30 GB）**
- 档 A：1,112.1 ms（**−42.74%**）/ 29,465.3 sps（**+74.63%**）/ MFU 13.44%
- 档 B：892.5 ms（**−54.04%**）/ 36,716.4 sps（**+117.62%**）/ MFU 16.75%
- 与论文 407 ms 并列：档 A **2.73×**、档 B **2.19×**

## 11 追加：权重 bf16 影子（E11）—— 逐位等价，但无收益

改动：`ONETRANS_WEIGHT_SHADOW=1`，按 `(param, 切片)` 在一个 step 内复用同一份 bf16 权重（`p[idx].transpose(...)/to(bf16)`），
缓存的张量仍接在原 Parameter 图上 ⇒ DDP / 重算 / 累加语义不变；step 末尾清缓存。

| 档（16 die · n=8） | 不开 | 开 | Δ | 吞吐 Δ | HBM |
|---|---:|---:|---:|---:|---|
| A 每卡 2048+重算 | 1,112.1 ms | 1,110.4 ms | **−0.15%** | +0.16% | 47.57→47.74 GB |
| B 每卡 1024×2 无重算 | 892.5 ms | 893.0 ms | **+0.06%** | −0.06% | 70.17→69.93 GB |

精度：UT（NPU，2 步×2 micro-batch，含 AdamW）loss 与 41/41 参数梯度**逐位相同**（rel = 0）。
踩坑：bmm 路径的 bias 必须留 fp32（baseline 靠 type-promotion 在 fp32 域相加），否则差 1 ULP。

kernel 侧（8 die 同档）：kernel 2,862→2,693（−169/步）；含 `Cast` 的算子 665→552 次，但 Cast 时长 84.8→84.5 ms（−0.3 ms）。

**结论：无效，默认关。** 归因更正：此前把反向 Cast（约 123 ms 的旧口径、E7 后约 78 ms）记成「权重 cast 往返」，
预估影子权重可吃掉 ~7%；实测被删的全是权重级小 cast（每次 ~0.02 ms），大头是**激活** cast（544 次、平均 0.14 ms），
上限只有 ~0.03%。**撤回该预估。**

## 12 追加：SDPA 内置 causal（G1，有效）

`paper_causal` 是底右对齐因果；实测 SDPA `is_causal=True` 在 `q≠k` 时是左上对齐（不等价，max|Δ| 4.26），
但在 **`q_len == key_len`** 的层两者同一张掩码 ⇒ 可直接省掩码张量、走 FA 内置 causal。
适用 base block + 第一个 pyramid block（1203×1203，约占 attention 前向算力一半）。

| 档（16 die · n=8） | 前 | 后 | Δ | 吞吐 | MFU |
|---|---:|---:|---:|---:|---|
| A 每卡 2048+重算 | 1,112.1 ms | **1,053.5 ms** | **−5.27%** | 29,465.3 → 31,104.8 sps（+5.56%） | 13.44% → **14.19%** |
| B 每卡 1024×2 无重算 | 892.5 ms | **847.3 ms** | **−5.06%** | 36,716.4 → 38,672.9 sps（+5.33%） | 16.75% → **17.64%** |

精度：模型 logits 与显式 mask 路径**逐位相同（max|Δ| = 0.0）**。开关 `ONETRANS_SDPA_CAUSAL=1`（默认关）。

**累计（起点 1,942.1 ms / 16,872.3 sps / MFU 7.70%）**
- 档 A：1,053.5 ms（**−45.75%**）/ 31,104.8 sps（**+84.35%**）/ MFU 14.19% ⇒ 对论文 407 ms **2.59×**
- 档 B：847.3 ms（**−56.37%**）/ 38,672.9 sps（**+129.20%**）/ MFU 17.64% ⇒ 对论文 407 ms **2.08×**

## 13 追加：全量投影 + 原地覆盖 NS 行（G2）—— **单卡有效、16 卡无效**

改法：`_project_one` / `cal_mix_param_ffn` 先全量投影（NS 行用共享权重），再把 NS 行整块覆盖为独立权重结果，
省掉「alloc + 两块写」的合并。开关 `ONETRANS_FULL_PROJ=1`。

| 场景 | baseline | G2 | Δ |
|---|---:|---:|---:|
| 单 die batch 1024 | 421.2 ms | **374.9 ms** | **−11.0%** |
| 16 die 档 B | 847.5 ms | 847.3 ms | −0.02% |
| 16 die 档 A | 1,053.5 ms | 1,053.8 ms | +0.03% |

精度（单 die 2 步，81 参数全梯度）：loss rel ≤ 9e-5；`max|Δg| = 4.88e-4` = 最大梯度元素的 **1 bf16 ULP**；
各参数 `max|Δg|` 中位数 7.6e-6 ⇒ 布局类 bf16 噪声级等价，**不可当精度基线**。

**判无效，默认关。** 结论性教训：内存/布局类优化在单 die 上的收益不能外推到 16 卡（16 卡被 cube 与 HCCL 掩盖），
收益判定必须在 16 卡做；单卡只用于精度与单算子耗时。

## 14 追加：FA `BSH` 布局（G3）—— 单卡有效、16 卡无效

| 场景 | baseline | G3 | Δ |
|---|---:|---:|---:|
| 单算子 fwd | 2.215 ms | 1.513 ms | −31.7% |
| 单 die batch 1024 | 421.1 ms | 409.8 ms | −2.7% |
| 16 die 档 B | 847.3 ms | 847.3 ms | 0.00% |
| 16 die 档 A | 1,053.5 ms | 1,054.0 ms | +0.05% |

精度：单算子 fwd 逐位相同、dk/dv 逐位、dq 1 ULP；模型级 2 步 max|Δg| = 2.44e-4（0.5 ULP），worst rel 7.6e-3。

两个坑：① FA `atten_mask` 语义是 True=屏蔽（与 SDPA 相反，传反不报错但全错）；② `Lq == ns_len` 那层 q 是
fp32 非连续（bmm+fp32 bias 的 type-promotion），FA 报 161002 ⇒ 该层留在 SDPA。

**判无效，默认关。** 连续三项（G2/G3 及其子项）都是"单卡有收益、16 卡为零"，说明
**16 卡的墙钟不由这些 kernel 决定**，必须换诊断方向：先量 16 卡的 kernel 并集 vs 墙钟、气泡与同步等待。
