OneTrans-S 在昇腾 950DT 的训练性能复核报告 v2

  • 日期：2026-11-16（v2：补第四步「权重 bf16 影子」无效结论，并更正 Cast 归因）
  • 目标：按论文 arXiv:2510.26104 的 OneTrans-S 形状（91 M 参数、d=256、H=4、seq 1190→12、6 层 pyramid、per-GPU batch 2048）在 16 卡 950DT（2×8 die，122 + 111） 上跑起来，实测步时/吞吐/MFU/显存，与论文 16×H100 的 407 ms 并列对比（只做训练，不含推理）
  • 代码与原始数据：github.com/xiaomingyao/OneTrans-S（main，含 results/prof*_kernel_details.csv 全部 profile 原始件）

2 口径纪律（先读这段，否则数字会被误读）

  1. 不与论文相除算「收益%」：论文 407 ms 是 fp32 未优化基线，本仓是 bf16 + FA 融合 + 融合 norm 档；只能并列。
  2. 档 B 的 per-GPU micro-batch 是 1024×2，论文是 2048 ⇒ 档 B 只在「全局 batch / 卡数」这一轴上对齐，不可与档 A 混读。
  3. 档 A 与档 B 的数学目标相同（micro-batch 均值 ÷ 累加数 = 整批均值），但 bf16 重排 + AdamW 非线性会让 loss 轨迹分叉 （step4：0.93893 vs 0.92159）⇒ 不可逐值比对、不可当精度回归。
  4. cat_inplace 这一步只改内存写路径，写入值相同；新缓冲的地址/对齐变化会改变下游 kernel 的分块与 fp32 累加顺序 ⇒ loss 相对差 ≤2e-4（step0 完全一致 0.69804）⇒ 记为 bf16 噪声级等价，可用于性能档，不可当精度基线。
  5. 训练数据是合成 token 常驻 device，步时不含取数/H2D（纯计算口径）。

3 优化逐项（三步有效 + 一步无效，每项都有 kernel 级证据）

3.1 ns-layout：NS-token 专有 QKV/FFN 由「逐 token Linear」合成一次 bmm

  • 动机：12 个 NS token 各有自己的 QKV/FFN 权重，原实现每 token 发一个 1-token matmul（每 block 12×3 次）。
  • 开关 ONETRANS_NS_BMM=1；CPU UT（tools/probes/ut_ns_bmm_equiv.py）：参数量 471,938 一致、前向 max|Δout| 5.96e-08、 反向 worst rel|Δg| 1.34e-06（判据 ≤1e-5）⇒ 等价通过。
  • 实测（16 die，全局 32,768）：1,942.0 → 1,442.9 ms（−25.70%），吞吐 16,873.0 → 22,710.2 sps（+34.60%），MFU 7.70% → 10.36%。
  • 独立复跑三次一致（−25.7% / −26.1% / −25.7%）。

3.2 融合 rms_norm：手写 norm 链换成 torch_npu.npu_rms_norm

  • 动机：profile 显示手写链（float→pow→mean→rsqrt→mul→改dtype→乘 fp32 weight）实际占 ≈280 ms/步（19%）， 其中 Mul 单项 151.6 ms（因为 bf16 × fp32 weight 会把张量提成 fp32 再走一遍向量运算）。
  • 开关 ONETRANS_FUSED_NORM=1；精度反而更好：对 fp64 参考 max_rel 3.891e-03 / rms 1.655e-03，手写链是 7.704e-03 / 2.347e-03 （单算子探针 tools/probes/probe_fused_norm.py，b64/seq1203，0.063 vs 0.205 ms/call）。
  • 实测（16 die）：1,443.9 → 1,228.6 ms（−14.90%），吞吐 +17.52%，MFU 10.35% → 12.17%，HBM 52.27 → 47.57 GB，kernel 3,083 → 2,762/步。
  • 逐算子：Mul 151.6→0、Square 27.9→0、Divs 22.2→0、Pow 14.4→0、Mean 13.1→0、ReduceSum 32.2→19.1、Add 130.8→109.0； 新增 RmsNorm 29.7 + RmsNormGrad 35.1 ⇒ 净 ≈ −213 ms。

3.3 去 cat：_project_one 的 seq/ns 合并改「预分配 + 原地写」

  • 开关 ONETRANS_CAT_INPLACE=1；只改内存写路径。
  • 逐算子（8 die 同档 profile）：Cat_ConcatD 51.4→7.8、Cat_CastAiCore 42.2→6.4、InplaceCopy_Cast 143.1→78.5、 InplaceCopy_Transpose 76.6→26.6；新增 FA 附属转置 27.9、ViewCopy +22.6、TensorMove +21.9；整步 1,235.1 → 1,121.7 ms。
  • 实测（16 die）：档 A 1,228.6 → 1,112.1 ms（−9.48%）；档 B 959.2 → 892.5 ms（−6.95%）。

3.4 第四步：权重 bf16 影子（ONETRANS_WEIGHT_SHADOW=1）—— 逐位等价，无收益

  • 动机：autocast 每次 F.linear/bmm 都把 fp32 权重现 cast 一遍；重算 + 梯度累加下，同一权重每步被 cast 三次。
  • 做法：按 (param, 切片) 缓存一份 bf16 权重，每步每权重只 cast 一次；缓存张量仍接在原 Parameter 的计算图上 （p[idx].transpose(...).to(bf16)）⇒ DDP 梯度同步、激活重算、梯度累加语义全不变，无新增叶子张量。
  • 精度（UT tools/probes/ut_weight_shadow_equiv.py，NPU、2 步 × 2 micro-batch、含 AdamW）： loss 与 41/41 参数的梯度逐位相同（rel = 0）。
  • 踩坑：bmm 路径的 bias 必须保持 fp32。baseline 的 bmm(bf16) + fp32 bias 靠 type-promotion 在 fp32 域相加， 把 bias 一起 cast 成 bf16 会让加法落到 bf16 域，logits 差 1 ULP（9.766e-04）、2 步 loss 相对差 3.4e-4。
  • 性能（16 die，n=8）：档 A 1,112.1 → 1,110.4 ms（−0.15%）；档 B 892.5 → 893.0 ms（+0.06%）；HBM 47.57 → 47.74 GB。

判定：无效，默认关。 kernel 侧证据（8 die 同档 profile）：kernel 总数 2,862 → 2,693（−169/步）、 名字含 Cast 的算子 665 → 552 次，但 Cast 总时长只从 84.8 ms 降到 84.5 ms（−0.3 ms） ⇒ 删掉的是权重级小 cast（每次约 0.02 ms），剩下约 78 ms 全是大张量激活 cast（544 次、平均 0.14 ms）。

归因更正（自我纠错）：此前把反向 Cast 记成「权重在 autocast 边界往返」并预估影子权重可吃 ~7%， 实测上限只有 ~0.03%，该预估撤回。

5 瓶颈分析证据链

5.1 整步被「算 4 遍」，不是 kernel 效率低

用 --no-backward 只跑前向做对照（8 die · 每卡 2048）：

段耗时/步kernel/步单遍效率
仅前向309.2 ms643MFU 48.24%
完整步1,235.1 ms2,76212.17%
⇒ backward(+opt)925.9 ms2,119—

分解：真反向 925.9 − 309.2 = 616.7 ms ≈ 2 × 309.2（反向 FLOPs 是前向 2 倍），单遍效率 48.5% 与前向一致 ⇒ 前向 1 遍 + 重算 1 遍 + 真反向 2 遍 = 4 遍算力，整体 MFU 12.17% ≈ 48.4% ÷ 4。

5.4 attention 落点核对（FAv4 生效）

aclnnFlashAttentionScoreV4 前向 7 次/步 + aclnnFlashAttentionScoreGradV4 反向 7 次/步（7 个 block 各一次，前向因重算出现 14 次）， kernel 列表里无 BatchMatMul + Softmax 的注意力回退链（Softmax 只出现在交叉熵）⇒ bool mask 路径确实落到 FA 融合算子。

6 未闭合项

  1. 结构对账：本仓每样本 31.53 GFLOP（CPU 探针），论文 Table 2 折算 1.29 GFLOP/sample ⇒ 24.5×；pyramid 开关比 1.68× vs 论文 3.06×。 说明本仓只剪 query token、不剪 K/V/FFN，结构与论文不完全一致（README §6）。
  2. Cast 仍 84.8 ms/步（665 次），其中约 78 ms 是 544 次大张量激活 cast（均 0.14 ms/次），来自 autograd 边界的 bf16/fp32 往返；权重影子实测只能拿掉 0.3 ms（§3.4），要继续啃得改激活的 dtype 流（结构性）。
  3. FA 反向 158.9 ms/步（7 次），按理论 ≈36% 效率，是 cube 里效率最低的一项；进一步要靠 attention 分块/算法级改动。
